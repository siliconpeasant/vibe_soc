## Timing Analysis

generic-gate path delay rules of thumb (NAND2 ≈ 0.05 ns, mux ≈ 0.15 ns,

The longest combinational path is the **8-bit counter increment + terminal
comparison + feedback mux** to the D pin of `cnt_reg`:

- The flattened netlist preserves both DFFs (`cnt_reg[7:0]`, `done_reg`) as
  posedge-clk / async-active-low-clear flops (`$_DFF_PN0_`), matching the RTL
  `always @(posedge clk or negedge rst_n_in)` semantics.

## Recommendations
1. **dont_retime**: The SDC explicitly notes that `cnt_reg`/`done_reg` must
   **not** be retimed (otherwise `STRETCH_CYCLES` semantics break). Yosys 0.9
   `flatten` did not retime, but downstream synthesis to Liberty cells should
   add `set_dont_retime [get_cells -hier u_rst_cnt/cnt_reg*]` and the same
   for `done_reg`.
2. **Adder structure**: `cnt + 1` is currently a ripple-carry chain. For
   CNT_WIDTH ≤ 8 this is fine; if `CNT_WIDTH` is parameterised up to ≥ 16,
   force a carry-lookahead via `synth -abc9` or pre-decompose with `+1`
   constant-input simplification.
3. **Async reset path**: `rst_n_in` drives 9 async-clear pins. In real
   technology mapping ensure the reset is buffered (max fanout) before the
   clear network; this is a back-end concern, not a synthesis defect.
4. **Parameter sweeps**: Re-run synthesis for `CNT_WIDTH=16` / `=32` if the
   module is intended to support long stretch windows — the ripple-carry
   critical path will scale ≈ 0.1 ns per bit and may dominate at ≥ 50 bits.
